# Opus 5.5 package audit

Claude Code reviewed commit `014b912` with model `claude-opus-5-5` on 2026-11-02.
The audit used read-only file tools and returned **integrate after fixes**.
It recommended keeping the abstraction as a protocol with reference implementations.

The first target has a Rust backend, a strict same-origin CSP, tenant-scoped API calls, and shared UI components.
The audit received those architectural constraints without credentials or application data.

## Findings and changes

| Finding                                                          | Change                                                                        |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Cross-language format and delivery rules were implicit.          | Add `docs/protocol.md` and published golden fixtures.                         |
| Conversation capture required a blob worklet.                    | Publish a static worklet and accept a same-origin URL.                        |
| Validation failures froze the submitted form.                    | Restore editing after definite validation rejection and use a new ID.         |
| Bare CR could escape literal feedback formatting.                | Normalize CRLF and bare CR before indenting every line.                       |
| Uncertain delivery had no operator signal.                       | Expose pending reasons and a review signal after five non-transient attempts. |
| Reconciliation unnecessarily scanned beyond the creation window. | Stop after checking a page that passes the wider ten-minute window.           |
| Late receipt responses could restore an obsolete report.         | Fence responses by scope, generation, and reference.                          |
| Hosts had to duplicate submission state.                         | Export `useFeedbackSubmission` independently of the default widget.           |
| Normal coordinator shutdown left locks and workers behind.       | Handle signals, stop process groups, and remove the lock.                     |
| Worker descendants could survive timeouts.                       | Signal the process group and bound inherited-stream cleanup.                  |
| Issue edits caused automatic repeated work.                      | Record `changed_since_run` and require explicit replay approval.              |
| Spoken replies could enter the microphone.                       | Pause capture during replies by default, with explicit headphone barge-in.    |
| A failed GitHub poll stopped watch mode.                         | Retry transient poll failures without discarding job state.                   |
| Initial voice discovery could return an empty list.              | Wait for the initial `voiceschanged` event.                                   |
| Over-length voice text changed the source before validation.     | Check the length first and cache successful transcription for retries.        |
| Identity changes could retain a draft or pending voice result.   | Reset state and ignore or cancel obsolete work.                               |
| Unsupported browsers showed a screen-capture action.             | Hide capture when `getDisplayMedia` is unavailable.                           |

## Clarifications

The server reference uses Web APIs and needs a JavaScript runtime.
A Rust application implements the documented protocol in its existing backend.
It does not need a second JavaScript service.

An awaited creation-intent callback narrows the crash interval but cannot remove it.
A crash after the intent commit can still require operator reconciliation.
A bounded scan can also exceed its limit in a busy repository.
The review signal makes those cases explicit without risking duplicate creation.

Legacy marker support remains available through an explicit namespace option.
The generic coordinator contains no product-specific namespace.

## Validation

All 31 package tests passed.
They cover formatting, protocol fixtures, delivery, form recovery, receipt races, voice lifecycle, process cleanup, replay prevention, and poll recovery.
The first Rust host integration remained on hold until the follow-up review below.

## Follow-up review

Claude Opus 5.5 re-audited commit `bc5c675` and returned **ready for host integration**.
It confirmed the original findings were fixed and covered by tests.
It identified three low-severity delivery cases that caused unnecessary operator work:

- A nearly exhausted deadline could record intent without sending a POST.
- Invalid local inputs could appear to be uncertain creations.
- A transient outage could clear an existing review signal.

The next patch adds creation-budget checks, typed local rejections, and a persistent review flag.
It also provides a manual status check after an operator resolves delivery.
Regression tests exercise each case.
